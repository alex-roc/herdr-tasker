Ways to work with it

A bug fixed in its own worktree

You're in the middle of something on main and a bug report comes in. You want an agent on it without touching your checkout.

  1. Press n. Title: Checkout total ignores the coupon. Pick the repository, due today, next step Write a failing test first, then press t to put it at the top.
  2. Press w. tasker creates task/checkout-total-ignores-the-coupon in ~/.herdr/worktrees/<repo>/… and starts your agent there, with the title and the next step as its first message.
  3. Keep working. The task sits under Working with the agent's model and time; you'll see it jump to Needs you if it asks.
  4. When it stops, the task is in To review. Open the detail, check Changes, then Ask for a pull request.
  5. If CI fails, Send failed checks sends the agent their names. When the PR is merged, right-click → Archive and choose Archive and remove worktree.

Issues into a week of work

GitHub or Linear has a pile of open issues and you want a plan you can actually work through.

  1. In Projects, right-click the repository → Import GitHub issues (or Import Linear issues for the ones assigned to you, most urgent first, with their due date). Tick the ones worth doing; they arrive in the Inbox with the issue's link and text attached.
  2. Open the board (cmd shift b) and drag what you'll do this week from Inbox to Next.
  3. In the list, drag the tasks of Up next into the order you'll do them, and give due dates like wed or fri.
  4. Start an agent on the top one with l. It gets the issue's text in its first message, so it starts with the full report.

Issues you've already imported don't show up again in the list.

Back after a reboot

The machine restarted overnight. Three tasks had agents mid-conversation.

  1. Open Herdr and switch to tasker. The tasks are where you left them; their agents are gone.
  2. Select the first one and press r (or Resume agent in the detail). Its Claude Code or Codex conversation continues in the folder it was in, in a new tab tied to the task.
  3. Do the same for the others. Each moves back to Doing as soon as its agent starts working.

Glance at the status bar before you start a big batch: it shows how much of your Claude and Codex limits is left, and when each resets.

Several agents, one list

Three agents on three tasks, maybe in different repositories. You want to spend your attention where it's needed, not cycle through tabs.

  1. Start each from its task (l or w). Each opens in its repository's space.
  2. Stay in Now. Whatever is blocked is on top with its question; finished work is next; working agents after that.
  3. Answer from the detail's Message the agent box, or enter to jump to the agent.
  4. Herdr's next and previous agent keys follow tasker's order, so they visit the agents in the order the list shows them.

Set a Doing limit in the settings (the gear in the status bar) to keep yourself honest: the status bar warns when you have more in progress than that.

Track work already started

You opened a terminal and started an agent before thinking of it as a task. Now it's grown.

  1. Find its tab in the list: under its repository in Projects, or in Now if it's working, finished or waiting on you. It's named after its title, or what runs in it and where, like zsh · acme-web.
  2. Click Make task. tasker creates a task named after the tab and tied to it: in Doing if the agent is working, Review if it finished, Next if it's idle. On the board, drag its card from the No task lane onto the column you want instead.
  3. Or right-click it → Add to task… and pick an open task: the tab joins that task.
  4. Press e to give it a real title, a project and a due date. From now on it moves with its agent like any other.

Agents that file their own tasks

An agent finishes a job and notices three more things worth doing. You'd like those in your Inbox, not lost in its scrollback.

Tasks live in one JSON file that tasker reloads within a second of any change. Add this to your agent's instructions (AGENTS.md, CLAUDE.md, or the prompt):

When you find follow-up work outside your task, add it to my task list as an
Inbox task instead of doing it: append to the "tasks" array of
~/.config/herdr-app/data/tasker/tasks.json an object with "id" (agent-<timestamp>),
"title", "repo" (~/path), "status": "inbox", "notes" (why), "priority": "high"
only when it can't wait (it goes first; otherwise last),
"created" and "updated" (ms since epoch) and "history": [{"s": "inbox", "at": <ms>}].
Keep every other field as it is, write to a temp file and rename it over the
original. Never mark my tasks done and never delete them.

The full rules, with Node and shell examples, are in docs/agents.md. tasker checks every field it reads, so a slightly wrong entry still shows up, and it never writes over a file it can't parse.

Capture a task from any terminal

An idea comes up while you're in a shell. You want it in the Inbox in one line.

Add this function to your ~/.zshrc or ~/.bashrc (it needs jq):

todo() {
  local f=~/.config/herdr-app/data/tasker/tasks.json now=$(($(date +%s) * 1000))
  local repo=$(git rev-parse --show-toplevel 2>/dev/null | sed "s|^$HOME|~|")
  [ -f "$f" ] || echo '{"tasks":[]}' > "$f"
  jq --arg t "$*" --arg r "$repo" --arg id "cli-$now-$RANDOM" --argjson n "$now" \
    '.tasks += [{id: $id, title: $t, repo: (if $r == "" then null else $r end),
      status: "inbox", created: $n, updated: $n, history: [{s: "inbox", at: $n}]}]' \
    "$f" > "$f.tmp" && mv "$f.tmp" "$f"
}

Run inside a repository, the task is tied to it, so it shows under that repository in Projects.

Drive tasker from scripts

You want a shortcut, a launcher or another tool to open tasker's views.

tasker answers these commands while its layout is on screen:

herdr-app do tasker.new             # the New task form
herdr-app do tasker.jump            # find a task
herdr-app do tasker.board           # open (or go to) the board
herdr-app do tasker.view            # switch Now and Projects
herdr-app do tasker.settings        # the settings
herdr-app do tasker.select:<id>     # show that task's detail
herdr-app do layout.toggle '{"id":"tasker-detail"}'  # show or hide the detail

For example, a Raycast or Alfred command that runs herdr-app do tasker.new gives you a global "new task" key.

A weekly review

Friday afternoon. What moved, what's stuck, what's next.

  1. Stalled in Now lists Doing and Waiting tasks that haven't moved in a few days (you set how many). Decide each one: back to Next, Waiting with a note, or Dropped.
  2. The board's Done column shows the last seven days; the status bar counts what you finished today.
  3. In Projects, the eye button shows finished tasks too. Archive what's settled to put its tabs away.
  4. Drag next week's work from Inbox onto Up next, in the order you'll do it.
